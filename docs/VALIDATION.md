## 本地验证

```powershell
python -m pytest -q
node --test tests/test_userscript_links.cjs
python scripts/benchmark.py
```

基准生成 8 秒合成和弦、谐波、打击噪声，输出在 `output/benchmark-cs2/`。`original.wav` 为原音频，`carrier.wav` 为扰乱音轨，各 `*_decoded.wav` 为恢复音频；`results.json` 为实测数据。演示密钥为 `demo-music-key`。

当前 CS2 本机测试结果（不是 B 站实测，也不是对真实音乐的主观音质评分）：

| 转码 | 恢复音频包 | 相对原样本 SNR |
| --- | --- | --- |
| PCM WAV | 8 / 8 | 28.49 dB |
| AAC 256 kbps | 8 / 8 | 27.04 dB |
| AAC 128 kbps | 8 / 8 | 21.79 dB |
| AAC 96 kbps | 8 / 8 | 19.22 dB |
| Opus 128 kbps | 8 / 8 | 21.10 dB |
| AAC 128 kbps / 44.1 kHz | 8 / 8 | 21.12 dB |
| AAC 256 kbps → 二次 AAC 128 kbps | 8 / 8 | 21.61 dB |

`pytest` 测试覆盖 PCM 恢复、错误密钥、任意分块、从中途加入、噪声输入的缓冲上限、访问令牌/Origin、WebSocket 音频往返、多音轨视频的音轨替换和失败输出清理。新增测试覆盖短时声音的整秒扩散、能量保持、拒绝旧版正导频及重新同步和非有限编码输入；油猴兼容性测试覆盖 CS2，需要 Node.js，直接加载发布的单文件脚本，对比 Python 的密钥映射与解码输出，覆盖中文/emoji 密钥、中途加入、任意分块、无效输入和 AAC 128 kbps / 44.1 kHz 转码；两种样本与 Python 输出的误差信噪比均超过 100 dB。缺少 Node.js 时两项油猴测试会跳过。基准脚本实际调用 FFmpeg 转码。二次 AAC 测试模拟先生成上传视频，再经平台重新编码的过程，但不代表实际平台参数。


## B 站回归验收步骤

1. 选一段你有权使用的 30–60 秒音乐/人声视频，编码后先离线恢复试听。
2. 上传编码版，等平台转码结束；直接播放应听到扰乱的声音。
3. 用油猴解析当前视频音轨，测试分 P、备用链接、暂停、跳转、倍速和至少 10 分钟连续播放；确认停止后恢复静音状态。
4. 检查音乐可懂度、噪声、丢包与音画延迟；如能取得平台转码音频，再运行离线解码区分浏览器解码问题和平台转码问题。
