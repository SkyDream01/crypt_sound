# CS2 格式与技术边界

[返回首页](../README.md)

## 音质、延迟和边界

- 每秒一包：2048 点公开同步导频、256 点保护间隔、45056 点扰乱音频和末尾保护间隔，合计 48000 点。同步导频只用于定位，不包含原始音频。
- 每包原始一秒音频重采样进有效载荷，分成 44 个 1024 点 DCT 块；保留密钥决定的 16 个频带置换、反转和符号变换。CS2 在每块的 640 个有效频点上施加独立的密钥符号掩码，再沿 44 个时间块做正交 DCT 扩散，最后施加第二组符号掩码。解码按逆序恢复；正交扩散本身不损失能量，也不增加包时长。高频主动截断，实际恢复带宽约 14 kHz；有些高频乐器细节会损失。
- CS2 掩码由独立 PBKDF2-HMAC-SHA256 域 `crypt-sound-CS2`（100000 次迭代）导出；SHA-256 扩展输入为种子加三个单字节 `domain, block, counter`，每行取前 640 位，按每字节低位优先映射为 ±1。两个声道共用掩码，兼容单声道源。仅接受 CS2 的负导频，正导频被跳过。频带映射仍使用历史盐 `crypt-sound-CS1`，这是 CS2 格式的一部分，不代表支持 CS1。掩码固定、没有随机 nonce 或认证标签，不能视为密码学加密；应避免对音轨整体反相，否则会影响格式识别。
- 原音轨有短周期同步信号，因此未解码声音可能很刺耳。不要直接以高音量试听。
- 油猴按已解密进度调度最多两秒的独立音频片段，按原音轨时间位置跟随视频播放；暂停或跳转会立即停止旧声音，播放中定期校正超过 0.2 秒的偏差。支持播放器倍速，但 Web Audio 变速会同时改变音高；不保证采样级口型同步。Python 工作台的可选实时捕获仍约有 1–2 秒启动延迟，不支持倍速。
- 自动寻找同步信号；油猴将完整音轨 PCM 保存在内存，跳转复用已恢复的音频。平台损坏的包不能恢复，没有丢包补偿。
- 末尾不足一秒的内容补零，离线恢复可能多出不到一秒静音；没有长度元数据。离线解码的丢包不会补时长。
- 经有损转码不能无损恢复。低码率、重度降噪、变速、时间伸缩、削波、删除导频或平台后续算法变化均可能使同步失败或音质明显下降。切换到低清码率也可能影响效果。
- 稳定密钥映射便于实时恢复，但会泄漏结构。这不满足真正的保密性和完整性要求，不应把它用于敏感数据保密。
