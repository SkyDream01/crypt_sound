# 加解密原理（CS2）

[返回首页](../README.md) · [格式参数与技术边界](FORMAT.md)

这里的“加密”是为了让音轨在播放时听起来被扰乱，同时尽量允许平台有损转码后恢复声音。它不是密码学加密：没有随机 nonce、完整性认证或保密性保证。请勿用它保护敏感内容。

## 一眼看懂处理链

```text
原音轨 ──解码、统一采样率──> 48 kHz 双声道 PCM
       ──每秒分包、缩入载荷──> 频域与时间域密钥扰乱
       ──加入同步导频──> CS2 音轨 ──可替换视频音轨 / 被平台转码──>
       ──寻找导频、取出载荷──> 逆向变换、恢复一秒 PCM ──> 播放或保存 WAV
```

画面没有参与扰乱。处理视频时，FFmpeg 读取第一条音轨并转换为 48 kHz 双声道 PCM；输出只保留第一条视频流，复制画面，并用 CS2 音轨替换原音轨。纯音频可输出 WAV。恢复文件输出 WAV；浏览器油猴脚本则从视频对应的独立音频流取得 PCM，在本地恢复播放。

## 一个音频包长什么样

编码器把原音频每 **48,000 个采样点（1 秒）**做成一个同样长的包。末包不足一秒时补零；CS2 不记录原始样本数，因此解码结果按整秒输出，末尾可能多出不足一秒的尾段。每个声道采用同一包结构：

| 包内位置 | 长度 | 用途 |
| --- | ---: | --- |
| 开头 | 2,048 点 | 固定的负极性扫频同步导频，用于在音轨中找到包起点 |
| 导频之后 | 256 点 | 静音保护间隔 |
| 有效载荷 | 45,056 点 | 扰乱后的音频，分成 44 个 1,024 点块 |
| 末尾 | 640 点 | 静音保护间隔 |

导频公开且不携带原始音频或密钥。它帮助解码器在被截取、跳转或转码后的音轨中重新找到一秒包；正极性导频不会被当作 CS2 包。载荷比原来的一秒短，所以编码前用 Fourier 重采样把 48,000 点压缩为 45,056 点，解码后再重采样回 48,000 点。

## 密钥怎样决定扰乱方式

同一密钥总会生成同一套变换；包序号和文件名不参与派生。Python 编码器与浏览器解码器使用相同规则：

1. 把密钥按 UTF-8 编码，分别用频带映射盐和扩散掩码盐执行 100,000 次 PBKDF2-HMAC-SHA256，得到两组 256 位种子。两组盐的固定值见[格式参数](FORMAT.md)。
2. 第一组种子决定 16 个频带的排列及符号。每带 40 个 DCT 频点，共 640 点；每个频带内部也反转。排列会避开原位频带。
3. 第二组种子用 SHA-256 扩展成两张 **44 × 640** 的 `+1/-1` 符号表，分别用于时间扩散前和扩散后。两个声道共用这些表。

这里的符号变换只改变频率系数的正负号，不直接修改密钥文本。因为没有随机量，同一密钥对相同输入会产生相同结果。

## 编码：把能听懂的声音变成载波

对每一秒的两个声道，编码器依次执行：

1. 将 48,000 点重采样为 45,056 点，并拆成 44 个时间块。
2. 对每块做正交 DCT，把波形转为频率系数。固定保留前 640 个频点，再按密钥决定的频带顺序、带内反转和符号进行重排；其余系数不写入载荷。
3. 给每个时间块、每个有效频点乘第一张符号表；再对**同一频点在 44 个时间块上的数值**做一次正交 DCT，让一段短声音分散到整秒载荷；最后乘第二张符号表。
4. 将变换后的 640 个系数放到每块的低频位置，其余位置填零；对每块做逆 DCT，回到波形。载荷波形乘以 `0.22` 的增益，再放入带有导频和保护间隔的一秒包。

编码器会拒绝峰值超过 PCM 范围的包，避免输出时削波。分包后可把 CS2 音轨写为 WAV，或编码为 AAC 并替换视频音轨。

## 解码：按相反顺序恢复

解码器先在 PCM 中用导频的相关性寻找包起点，并检查导频极性。找到完整的 48,000 点包后：

1. 取出 45,056 点载荷并除以 `0.22`，拆成 44 个时间块。
2. 对每块做 DCT，取前 640 个系数；乘第二张符号表，沿 44 个时间块做逆 DCT，再乘第一张符号表。
3. 按密钥映射把系数放回原先的频率位置，并撤销符号变换；其余频点填零。对每块做逆 DCT，得到 45,056 点波形。
4. 重采样回 48,000 点，输出这一秒的双声道声音。

符号表中的 `+1/-1` 自身就是逆操作；正交 DCT 的逆变换也能撤销时间扩散。解码器丢失同步时会继续寻找下一段导频。Python 离线恢复会跳过无法识别的包；油猴播放按包在原音轨中的时间位置安排声音，缺失位置留静音。

## 为什么无法完全还原，也不能保密

- 编码只保留每个 1,024 点块中的 640 个 DCT 频点，再加上长度重采样，实际可恢复带宽约为 14 kHz；高频细节会损失。
- WAV 载波仍可能受采样量化影响。视频输出和平台再次转码还会引入有损压缩；降噪、变速、时间伸缩、削波或导频受损可能让同步失败或明显降低音质。
- 频带置换、符号掩码和时间扩散是固定的信号变换。导频、包时序、能量及重复内容仍可能泄漏信息；音轨也没有认证标签。错误密钥通常只会得到杂乱声音，不会触发“密钥错误”校验。
- 扰乱后的音轨及错误密钥恢复的声音可能刺耳，试听前请降低音量。原文件应另行保留。
